# 최종 검수 체크리스트 (PD — TTS 직전)

> 언제 쓰나: 사용자가 「○○ 대본 최종 검수해」라고 할 때. 파이프라인 검수(`script-review-checklist.md`, script-reviewer)를 통과한 **뒤에**
> 사용자 수정·외부 검토·리비전이 반영된 완성본을, TTS 비용이 나가기 전에 PD가 마지막으로 한 번 더 보는 단계다.
> 파이프라인 검수를 다시 돌리는 것이 아니다 — **수정이 쌓이며 새로 생긴 오류와, 문서끼리 어긋난 곳**을 잡는다.
>
> 기준 문서: 채널 `config/profile.md`(규칙 정본) · `config/style-ban.json`(린터) · `config/pd-guide.md`(제목) · `config/thumbnail-strategy.json`(썸네일) · 프로젝트 `_script/verified-data.md`(사실 정본)
> 실제 적용 예: `channels/reason-economy/projects/philippines-navy-gift-ships/_script/review.md` 「최종 검수」

---

## 0. 준비 — 무엇을 읽는가

- [ ] `_script/script.txt` **전문**을 처음부터 끝까지 읽는다 (발췌 금지 — 수정이 쌓인 곳은 앞뒤 문장과 어긋나 있다)
- [ ] `_script/verified-data.md` — 대본의 숫자·날짜·이름을 대조할 원본
- [ ] `_script/review.md` 기존 기록 — 이미 판정한 항목(「유지」「미반영」과 그 이유)을 확인해 같은 지적을 되풀이하지 않는다
- [ ] `output/02_썸네일제목.md` · `03_업로드정보.md` · `04_타임스탬프.txt` · `_script/artifact-url.txt`
- [ ] 다른 세션이 이 프로젝트를 작업 중인지 확인한다 (`ListAgents`) — 작업 중이면 파일을 직접 고치기 전에 사용자에게 「반영할까요」를 묻는다

## 1. 사실 정밀도 — 반올림·축약에서 틀어진 사실

파이프라인 검수는 「사실이 맞는가」를 본다. 최종 검수는 **수정·압축 과정에서 한 칸씩 틀어진 것**을 본다.

- [ ] **숫자·날짜를 verified-data와 한 줄씩 대조한다** — 특히 나이·기간·「○년 전/뒤」처럼 **두 날짜에서 계산한 값**
  - 예: 「넘겨받을 때 마흔다섯 살」 ← 1967-10 취역 → 2012-05 이양 = 44년 7개월 → 「마흔다섯 살 가까이」
  - 예: 「3년 앞섰다」 ← 2016-10 → 2019-08 = 2년 10개월 → 「3년 가까이」
- [ ] **verified-data에서 △·⚠️(출처 불일치·단일 출처)로 표시된 것이 대본에 단정형으로 들어갔는가** → 범위를 좁히거나 이름을 뺀다
  - 예: 함급명이 출처마다 다르면(제비급/학생급) 「고속정 열두 척」으로
- [ ] **사실 보호 표기가 살아 있는가** — 「잠정」「국제선 기준」「협상 중」「목표치」가 압축 중에 잘려 나가지 않았는지 (빠지면 치명)
- [ ] **시점 표현** — 수정으로 새로 들어온 「올해·작년·최근·지난달」이 없는지 (절대 연도로)

## 2. 합계·내부 일관성 — 대본이 스스로 말한 숫자끼리

- [ ] **대본이 말하는 합계를 세부 항목으로 직접 더한다** — 「22척 = 12 + 8 + 1 + 1」 「12척 = 2 + 2 + 6 + 2」 「인도 6척」
- [ ] 같은 숫자가 두 번 나오면 **두 곳이 같은 값인가** (훅의 숫자 = 본문의 숫자 = 클로징)
- [ ] 같은 대상을 **두 이름으로 부르지 않는가** — 「원해경비함/먼바다 경비함」, 「HD현대/현대중공업」(시기별로 다르면 시기를 맞춘다)
- [ ] **시간 순서가 거꾸로 들리는 연결어**가 없는가 — 2026년 사건 바로 뒤 「그리고 2025년 12월」 → 「앞서 2025년 12월에는」
- [ ] 「N년 뒤」를 **기준 시점이 다른 두 사건**에 쓰지 않았는가 (같은 사건으로 들린다)
- [ ] 전반에 연 질문·열린 고리(「잠시 뒤에」「앞에서 남겨 둔 질문」)가 **모두 회수됐는가** — 안 닫힌 고리는 치명

## 3. 채널 규칙 대조 — 수정 뒤에도 규칙이 지켜지는가

채널 `profile.md`가 정본이다. 아래는 「세상의 이유」 기준이며, 다른 채널은 그 채널 profile의 같은 항목으로 바꿔 본다.

- [ ] **훅 ⑤ 형식** — 역설 질문 → 「오늘은 그 이유를 말씀드리겠습니다」 → 「왜/어떻게 ~했는지 말씀드리기 전에, ○○부터 보셔야 합니다」(의문사는 역설 질문과 같게) → 새 장면. 두 문장 합쳐 90자 안팎
- [ ] **(지식대학) 훅 숫자 받아 주기** — 인트로에서 근거 숫자를 던진 직후 바로 「오늘은 ~알아보겠습니다」로 닫지 않았는가. 사이에 시청자 생각 받기(「숫자만 보면 ~같죠」) + 「그런데」 반전 예고 1~2문장이 있어야 한다. Hook & Intro 합계 250~320자 (profile 「훅 & 인트로 공식」 2-1, 2026-10-06)
- [ ] **뻔한 답 부정** — 부정하는 답이 대본 안에서 먼저 나왔는가(「흔히 ~을 꼽습니다」), 튀어나온 말이 아닌가
- [ ] **국뽕 80:20 (자부심 소재) — 자기반박은 조건부 (2026-10-08)**
  - **넣어야 하는 편인가**: ① 제목·숫자를 바로잡아야 하나(「브랜드 기준」「한 품목」) ② 앞으로 뒤집힐 위험이 있나 ③ 운·외부 요인이 섞였나 — 하나라도 해당하는데 블록이 없으면 지적, 아무것도 해당 없는데 억지 약점 블록이 있으면 지적
  - 블록이 있으면 **글자 수로 센다**: 4막 한 블록 · 반론 1개 · 2~4문장 · 약 200~300자 · 약점 고백이 아니라 숫자 바로잡기인가 · 결론과 축이 다른 반론(정책 비판 등)이 아닌가 · 마감 문장이 매 편 같은 상투구(「그래도 이 차이는 남는다」)가 아닌가
  - 블록 유무와 무관하게: 범위어(사실 보호)가 숫자 옆에 살아 있는가(빠지면 치명) · 본문에 흩어진 선 긋기(「다만」「물론」)가 대본 논지가 아닌 유보라면 지적
- [ ] **「앞으로 ~을 봐야 합니다」 지표·행동지침 단락이 없는가** (린터가 잡지만, 「궁금하시다면 …」처럼 변형이 있으니 클로징을 눈으로도 본다)
- [ ] **클로징 순서** — 훅 장면 회수 → 이제 보이는 이유 → 「쉽게 말해, ~」 핵심 메시지 → 다리 문장 + 「내 경험」 질문(답 길이 지정) → 아웃트로 고정 4줄(한 글자도 다르면 안 됨)
- [ ] **숫자 개수** — 전체 150개 이하, 한 문단 2개 이하 (`len(re.findall(r'\d[\d,.]*', 대본))`)
- [ ] **분량** — `len(대본.replace("\n",""))` ÷ 472 = 분. 채널 기준 범위(세상의 이유 20~25분) 밖이면 적는다(막지는 않음)
- [ ] **문체 린터** — `{VENV_PYTHON} scripts/src/style_lint.py _script/script.txt --channel {채널}` 통과
- [ ] **「~거든요」 용법 (전 채널)** — 린터가 `[확인]`으로 뽑아 준 「거든요」 문장을 하나씩 본다. 앞 문장 뒤에 「왜냐하면」을 넣어 말이 되면(이유·근거·배경) 통과, 안 되면(새 이야기를 꺼내는 문장, 결론·대조 사실) 「~습니다/~어요」로 고친다. 어미 섞기 규칙 때문에 리듬용으로 끼워 넣은 것이 대부분이다 — 지식대학 고양이 보름달 편 초안에서 13회 중 5회 (profile 「말투」·「어미 섞기」, 2026-10-05 사용자 결정)
- [ ] **TTS 위험** — 알파벳·특수기호가 남았는지(「FA-50」「HD현대」처럼 남겨 둔 것은 첫 생성 때 청취 확인 대상으로 적는다)

## 4. 완성본 파일 일치 — 업로드하는 것이 검수한 것과 같은가

- [ ] **`_script/script.txt` = `output/01_대본.txt`** (개행 차이 무시하고 비교)
- [ ] **아티팩트의 대본·제목·설명글·고정 댓글 = output 파일** (아티팩트 `const D` 의 값을 읽어 비교)
- [ ] **03 업로드정보·고정 댓글·02 썸네일 문구가 대본 표현과 어긋나지 않는가**
  - 대본에 없는 사실·숫자가 메타에 있는가 (예: 설명글 「호위함·경비함 12척」 ← 대본은 초계함 포함)
  - 대본은 범위어로 썼는데 메타는 단정했는가 (예: 대본 「30년 가까이」 ↔ 고정 댓글 「30년」)
- [ ] **제목·썸네일이 포장 규칙을 지키는가** — 제목 길이 상한 이하(실제로 센다 — 기본 40자, 채널 pd-guide 기준 우선: 세상의 이유 50자·앞 30자에 장치+주제 이름), 질문형 금지, 둘째 줄은 한국이 주어인 승리 단정(자부심 소재), 특정인 발언 따옴표 금지, 실존 정치인 얼굴 금지
- [ ] **04 타임스탬프**는 추정치 경고가 붙어 있는가 (분량이 바뀌었으면 「영상 완성 후 실측 교체」 안내만)

## 5. 고친 뒤 다시 돌린다

- [ ] 글자 수 · 숫자 개수 · 린터를 **수정 후에 다시** 잰다 (수정이 새 위반을 만든다)
- [ ] 자기반박 블록이 있으면 글자 수를 다시 센다
- [ ] `output/01_대본.txt` 복사 → `03` 수정 → 아티팩트 갱신(같은 URL — `artifact-url.txt`)

## 기록 형식 — `_script/review.md` 끝에 추가

```markdown
## 최종 검수 ({날짜}, PD)

> 대상: script.txt(= output/01 동일 여부) {글자 수}자 ≈ {분}분 · style_lint {결과} · 아티팩트 {URL}
> 대조: verified-data.md, 훅 ⑤, 80:20, 클로징 규칙

### 치명 — {N}건
(사실 오류·사실 보호 누락·안 닫힌 고리. 0건이면 확인한 것을 한 줄로: 「22척 합계 ✅ …」)

### 사실 정밀도 — {N}건
1. {행} 「원문」 — 근거(verified-data 위치·계산) → 「수정안」

### 톤·규칙 — {N}건
### 메타(output) — {N}건

### 유지 판단
- 일부러 고치지 않은 것과 그 이유 (사용자가 고른 문장, 대본 논지인 「다만」 등)
```

- 심각도 순서: **치명**(사실 오류·사실 보호 누락·안 닫힌 고리) > **사실 정밀도** > **톤·규칙** > **메타**
- 사용자에게는 같은 순서로 보고하고, 반영 여부를 묻는다. 반영한 뒤에는 그 프로젝트를 작업 중인 세션에 **변경 내역을 문장 단위로** 알린다(디스크 최신본 기준으로 작업하라는 당부 포함)
